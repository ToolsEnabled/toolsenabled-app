# ToolsEnabled speech runtime

This is a speech-only Pipecat sidecar for the existing selected ToolsEnabled
agent. It never creates a chat model, chooses an agent, executes tools, or
cancels agent work. Electron owns microphone permission and playback; native
WebRTC connects its audio track directly to this local worker. The app forwards
final user transcripts to its selected agent and sends only that agent's public
reply text back for synthesis.

The renderer's duplex controller cancels the selected agent through its existing
interrupt API on `speech.started`, before transcription finishes. It blocks
queued automatic sends in all views while speech or recognition is pending,
then combines finalized segments in speech order after 900 ms without continued
speech (in addition to the runtime's 650 ms VAD endpoint). Continued speech
resets that timer. A cancellation failure holds input instead of starting more
work. Empty recognition closes its segment but never starts a model turn.
Canceled generations and queued TTS chunks remain suppressed; continuation is a
new turn in the same agent conversation, not a paused provider request. Local
VAD/STT determines the endpoint without an extra chat-model request.

## Install and provision

Windows packaging requires the speech interpreter, locked dependencies and all
seven local model files. Users do not install Python or run setup commands.
Local speech still requires a supported NVIDIA CUDA GPU and the existing
explicit microphone/voice opt-in. Speech preparation runs in the separate
worker after the user starts voice.

The installer keeps this runtime in `resources/voice-runtime/bundle`. Models
and interpreter files are read-only inputs. Caches stay in the owning user's
runtime data directory, and the worker disables bytecode writes. Voice startup
reads only a small readiness marker; it never hashes model files or walks the
dependency tree on Electron's main thread.

For builders, `npm run pack:voice` packages an already provisioned environment
using `private/voice-runtime-source.owner.json` (`profileRoot`, `runtimeRoot`,
`noticesRoot` and `python`, all explicit absolute paths). The release cutter already carries
these private builder inputs into its detached checkout. Alternatively pass
`--profile-root`, `--runtime-root`, `--notices-root` and `--python` to
`tools/prepare-voice-runtime.mjs`. Preparation runs below normal priority,
checks every dependency against the lock and installed wheel records, checks
the model hashes, and creates a portable CPython layout with an isolated
`._pth` file. It never copies a venv, cached audio, wheel caches, transcripts,
credentials, bytecode, or Python console launchers. Generated bytes remain
ignored private build assets. `afterPack` checks the actual copied files and
refuses an installer missing speech assets; these checks do not run in the UI.
`noticesRoot` contains the exact files declared by `redistribution-assets.json`,
including upstream eSpeak sources/build scripts and the model licenses/cards.
Python's license and the installed wheels' license files travel with the bundle.

The following manual provisioning workflow is for build/development machines
and existing installations that predate the bundled runtime.

The tested environment is native Windows x64, CPython 3.13.3, an NVIDIA RTX 5060
Ti with 16 GB VRAM, and driver 610.88. The isolated environment uses Pipecat 1.8.1,
Faster Whisper 1.2.1 / CTranslate2 4.8.2, and Kokoro ONNX 0.6.1 / ONNX Runtime
GPU 1.24.4. Direct and transitive versions are pinned. CUDA 12, cuDNN 9, cuFFT,
cuRAND, NVRTC, and nvJitLink DLLs are installed inside the environment; there is
no system-wide Python or CUDA mutation.

From this directory, set the following task variables to explicit absolute paths
chosen by the host/owner: `$voiceProfileRoot`, `$voiceDataRoot`, `$voiceTempRoot`,
and `$voiceBasePython`. `$voicePython` is the installed environment's
`venv\Scripts\python.exe` path. Do not derive these values from inherited profile
or temp environment variables.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -ProfileRoot $voiceProfileRoot -Python $voiceBasePython -InstallRoot $voiceDataRoot -TempRoot $voiceTempRoot
& $voicePython -s .\prepare_models.py --profile-root $voiceProfileRoot --data-root $voiceDataRoot --temp-root $voiceTempRoot
& $voicePython -s -m unittest discover -s tests -v
& $voicePython -s -u .\smoke_test.py --profile-root $voiceProfileRoot --data-root $voiceDataRoot --temp-root $voiceTempRoot
```

`setup.ps1` requires the explicit owner fence and Python executable. The model
provisioner requires explicit profile, data, and temp paths. The normal
data/install root is the enclosing workspace's `deps/voice-runtime`.
Model downloads are explicit setup work and never occur
when a user starts voice. The provisioner downloads a pinned Faster Whisper
large-v3-turbo revision and Kokoro v1.0 assets, verifies sizes and SHA-256 hashes,
and uses adjacent `.download` staging files before installing complete assets.
These downloads require roughly 2 GB for model files, in addition to the Python
environment and its wheel cache.

The host's mandatory owner profile fence is enforced by `runtime_paths.py` and
the installer. All profile storage must stay under the explicit `profileRoot`,
with ancestor checks rejecting reparse points. Temp, model, cache, and DLL paths
never fall back to inherited profile environment variables. The host supplies
these paths from its existing owner fence; the renderer cannot change them.
Privilege level is inherited from the host; the runtime does not elevate or
lower it.

Pipecat and Kokoro depend on the `onnxruntime` distribution name, while CUDA is
shipped as `onnxruntime-gpu`. The two distribution names contain overlapping
module files. The installer pins both to 1.24.4 and force-installs the GPU wheel
last. Always repair/reinstall through `setup.ps1`; independently uninstalling
either distribution can remove shared module files. `pip check` passes in the
tested environment. The speech provider verifies CUDA registration and actual
model inference; merely listing a GPU does not make the runtime ready.

## Process contract

### Linux setup and repeatable GPU proof

Linux x86-64 was also exercised with CPython 3.12, an RTX 4070 Laptop GPU
(8 GB), and driver 535.288.01. Install `python3.12-venv` if the base interpreter
cannot create an environment. With explicit paths inside the owner's profile:

```sh
python3.12 setup-linux.py --profile-root "$voice_profile" --data-root "$voice_data" --temp-root "$voice_temp"
"$voice_data/venv/bin/python" prepare_models.py --profile-root "$voice_profile" --data-root "$voice_data" --temp-root "$voice_temp"
"$voice_data/venv/bin/python" -m unittest discover -s tests -v
"$voice_data/venv/bin/python" smoke_test.py --profile-root "$voice_profile" --data-root "$voice_data" --temp-root "$voice_temp"
```

`setup-linux.py` uses the existing pinned dependencies and installs the GPU ONNX
wheel last. `runtime_paths.py` loads the CUDA libraries from that fenced virtual
environment, so neither a global CUDA installation nor an inherited
`LD_LIBRARY_PATH` is needed. GPU enumeration alone is insufficient: the smoke
test must complete real synthesis over WebRTC, interruption, recognition, and
worker shutdown. It uses generated audio and does not certify a phone's
microphone, speakers, or an authenticated agent conversation.

### Worker startup

Spawn `venv/Scripts/python.exe -E -s -u <absolute-worker.py>` with `windowsHide: true`
and piped stdin/stdout/stderr. Do not use `-I`, which excludes sibling imports.
Write exactly one UTF-8 JSON line to stdin:

```json
{"token":"<random base64url token, at least 32 characters>","profileRoot":"<absolute owner profile fence>","dataRoot":"<absolute data root within fence>","tempRoot":"<absolute temp root within fence>"}
```

Keep stdin open for the lifetime of the child. EOF closes its active media
session and exits. The bearer is never a process argument or stdout field.
`-E -s` excludes inherited Python search-path/home settings and user site
packages. Successful startup prints one JSON line:

```json
{"type":"ready","protocolVersion":1,"port":49152,"pid":12345}
```

The example port/PID are illustrative; the worker binds its own ephemeral port
on `127.0.0.1`. Every HTTP request, including health, requires
`Authorization: Bearer <token>`. The worker rejects browser Origin headers and
non-loopback Host/peer addresses, sets no CORS grants, and disables access logs.
The Electron main process proxies these endpoints through narrowly scoped IPC;
the renderer never receives the bearer or cloud key. Health reports capability
and model presence; session creation loads and exercises the requested models.
Allow up to 360 seconds for a first CUDA initialization. Models remain resident
in the single worker and are reused between sessions.

| Request | Body / result |
| --- | --- |
| `GET /health` | `{protocolVersion:1,runtime:"pipecat",speechOnly:true,local:{gpuAvailable,cudaDevices,onnxProviders,models,cpuFallback:false}}` |
| `POST /sessions` | `{sessionId,targetAgentId,generation,provider}` returns 201 `{sessionId,targetAgentId,generation,speechEpoch:0}` |
| `POST /sessions/:id/offer` | `{type:"offer",sdp}` returns `{type:"answer",sdp,pc_id}` |
| `GET /sessions/:id/events?after=N&waitMs=25000` | `{events:[],lastSequence:N}`; bounded long poll |
| `POST /sessions/:id/reply` | `{targetAgentId,generation,speechEpoch,utteranceId,text,final}` returns binding and `{accepted:true}` |
| `POST /sessions/:id/interrupt` | `{targetAgentId,generation}` returns binding and incremented `speechEpoch` |
| `DELETE /sessions/:id` | Returns binding and `{closed:true}` after media cleanup |

Only one session is active. Close it before selecting another agent or changing
providers. Every new session needs a fresh ID. `generation` is the app's target
selection generation and never changes within a session.

`speechEpoch` starts at zero and increments on every VAD speech start or explicit
interrupt. The host captures it when associating a public agent reply with the
listening turn and includes it on all chunks of that reply. This prevents even a
delayed first chunk from reviving an interrupted answer. Do not substitute the
current epoch into an old reply. A 409 `stale_speech`, `stale_binding`, or
`stale_utterance` means that reply should be dropped. Agent work continues.

`text` contains incremental chunks, not cumulative snapshots. `final:true`
flushes any pending phrase; it may accompany an empty string. Reusing a finalized
or interrupted utterance ID is rejected. The host serializes reply requests and
does not blindly retry an ambiguously completed chunk.

## Browser media

Use an audio `sendrecv` transceiver with the microphone track, native
`RTCPeerConnection({iceServers: []})`, and an optional data channel named `voice`.
Wait for ICE gathering to finish before sending the offer. There are no STUN,
TURN, RTVI, chat, or remote media-server requirements. Forward the returned
`{type,sdp}` to `setRemoteDescription`; `pc_id` may be ignored. Attach the incoming
audio track to an audio element. Request echo cancellation/noise suppression and
keep microphone capture active while the assistant speaks. Pipecat's Silero VAD
detects speech starts and flushes queued synthesis/playback immediately.

The signaling/control listener is loopback-only. WebRTC uses local ICE host
candidates and DTLS/SRTP; it does not use an external relay. The browser and
worker must be on the same machine or a directly reachable network. For remote
web/mobile clients, the authenticated app host bridge carries signaling and
control to the computer; the worker's HTTP listener remains loopback-only.
Audio input is consumed by the recognition
processor and is never echoed to the output track.

## Events and limits

Every event carries `sessionId`, `targetAgentId`, `generation`, `speechEpoch`,
and monotonically increasing `sequence`. `transcript.partial` and
`transcript.final` additionally carry `text` and a VAD `utteranceId`. Local STT
segments long speech every ten seconds, emits accumulated partials for those
segments, and emits one final at the end of the utterance. Normal shorter turns
produce only the final transcript. Only final transcripts should create agent
messages.

Other event types are `speech.started`, `speech.stopped`, `playback.started`,
`playback.stopped`, `state`, and `error`. State values include `preparing`, `ready`,
`connecting`, `listening`, `disconnected`, and `closed`. Error events contain
`stage`, `code`, `message`, and `retryable`. HTTP errors use
`{error:{code,message,retryable}}`. Provider response bodies, audio, and keys are
never reflected in errors.

Input recognition queues at most three ten-second PCM segments. Text chunks
are limited to 4096 characters, each utterance to 32768, and queued speech to
16384 characters / 64 phrases. Event history retains 256 entries with text
limited to 8192 characters. Falling behind that history produces explicit
`event_gap` instead of silently losing an agent-targeted transcript. Reconnect
voice after that error. Once model preparation finishes, sessions stop if the
host does not poll for 90 seconds. Cold CUDA preparation is not treated as host
inactivity: the host is awaiting session creation and no microphone exists yet.
Audio and keys are held only in memory and discarded at session close; this
runtime never saves microphone recordings or transcript logs.

Local STT is forced to CTranslate2 CUDA/float16. Local TTS requires an active
CUDA execution provider, verifies real synthesis, and disables runtime provider
fallback. ONNX may still assign lightweight shape/control operations to CPU;
the speech model is not allowed to fall back wholesale to CPU. Silero VAD,
phonemization, codecs, and resampling are intentionally lightweight CPU work.

Optional cloud config is session-only:

```json
{"stt":"openai","tts":"openai","apiKey":"<user-supplied key>","sttModel":"gpt-4o-mini-transcribe","ttsModel":"gpt-4o-mini-tts","voice":"coral","language":"en"}
```

STT and TTS can be selected independently. Local/local is the default, with
`large-v3-turbo`, `kokoro-v1.0`, voice `af_heart`, and English. Cloud adapters call
only the fixed OpenAI speech endpoints; they never create a Responses, chat, or
Realtime reasoning session and never automatically switch providers. Cloud
quota exhaustion is `cloud_quota_exhausted`; rate limiting is
`cloud_rate_limited`; missing/rejected credentials are
`cloud_key_missing` / `cloud_key_rejected`. Local setup failures are
`models_missing`, `gpu_unavailable`, or `gpu_initialization_failed`.

## Validation and packaging

On 2026-09-04 the deterministic suite passed 28 tests covering target/epoch
binding, late replies, interruptions, bounded events, bearer/origin checks,
session cleanup, cold-start watchdog timing, and sanitized credential/quota
behavior. A real hidden worker
then completed the generated-audio WebRTC smoke in 17.13 seconds, including
10.26 seconds for fresh-process local model initialization. It received 199680
bytes of synthesized remote PCM, fed that audio back over WebRTC during another
reply, detected the barge-in, and transcribed exactly: "The blue lantern is on
the desk." It rejected an old-epoch reply and exited successfully after stdin
EOF. The first-ever CUDA warmup took 189.41 seconds while another GPU inference
was running; later initialization was substantially faster.

This establishes real dependency imports, CUDA STT/TTS, WebRTC audio and a `voice`
data channel, synthesis, synthetic VAD/transcription, stale speech rejection,
and process cleanup. It does not establish user microphone quality, acoustic
echo cancellation, cloud account access/quota, or physical speaker behavior.
Those depend on the app/device/provider and were not exercised by this worker.

A separate hidden native Chromium check also connected the app host to this
worker through a real RTCPeerConnection and HTML audio element. It received
nonzero audio, verified microphone permission before/after explicit start,
denied camera access, rejected stale speech after interruption, and confirmed
both Windows Python processes exited. Fresh CUDA caches took 226.335 seconds
to prepare in that run, within the host's six-minute preparation deadline.
The check used synthetic input and muted output, not a physical microphone,
speaker, or paid API call.

`source-manifest.json` is the complete copy list for an app source commit. Do not
copy `__pycache__`, wheel caches, models, venvs, logs, or probe reports into the
source tree. The app host must pass the external absolute `dataRoot` and use the
external environment's Python. This source staging folder does not launch,
replace, restart, or publish the LIVE app.

Linux setup also copies the pinned eSpeak phoneme data to `espeak-ng-data` directly
under the selected runtime root. Older bundled eSpeak builds cannot initialize
data paths of 160 UTF-8 bytes or more. The loader uses this shorter installed
copy when needed and refuses missing or overlong paths before native initialization.
Setup verifies existing bytes and refuses package symlinks or changed data.
