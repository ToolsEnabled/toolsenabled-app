ToolsEnabled

Getting started

You were handed an installer for a program that runs an AI assistant on your own computer with the permissions you choose, and keeps local records of its runs. This page takes you from installation to an assistant that answers you, then explains the pages, controls and their limits.

What you need first

  • A supported computer. ToolsEnabled has a 64-bit Windows 10/11 installer and a 64-bit Debian/Ubuntu Linux .deb package. macOS is not supported by these builds.
  • Room for the download and installed program. The download page lists the package size. Provider programs, Linux dependencies and local-model downloads need additional space.
  • An assistant program only if you want to run agents. ToolsEnabled does not bundle provider programs. Codex, Claude, Gemini and Grok can be installed and signed in from Setup; the available models and whether they can start from a tree are shown beside each row. A local model runs on this computer and has no provider sign-in. Provider charges and quotas belong to the provider, not ToolsEnabled.

Local features do not require a ToolsEnabled account or licence key. Provider installation, sign-in and online assistants need an internet connection. The Windows installer is per user; installing the Linux package requires administrator permission. There is no time-limited trial.

1. Getting the installer

Download it from toolsenabled.ai/download.

That page is the only place we publish installers, and it lists what it is offering: the file name, the exact size in bytes and the SHA-256 checksum. Check the address before you install anything — anywhere else offering a ToolsEnabled download is not us.

The download page lists the platforms and versions currently available. Choose the installer for your computer.

Somebody may instead have handed you the installer directly — a file transfer, a USB stick, or a link on a local network. That is a normal way to get it, and it makes the check below matter more, not less.

The Windows installer ends in .exe; the Linux package ends in .deb. Use the exact filename shown on the download page or supplied with your copy.

Check you got the right file

The download page gives the installer's exact size in bytes and its SHA-256 checksum, and whoever hands you a copy directly should give you the same two numbers. Check both before running it. On Windows, open Windows Terminal or PowerShell — press the Start button, type terminal, press Enter — and run these two lines against your copy:

Get-Item "$HOME\Downloads\ToolsEnabled-Setup-<version>.exe" | Select-Object Length
Get-FileHash "$HOME\Downloads\ToolsEnabled-Setup-<version>.exe" -Algorithm SHA256

On Linux, open Terminal and run:

wc -c "$HOME/Downloads/toolsenabled_<version>_amd64.deb"
sha256sum "$HOME/Downloads/toolsenabled_<version>_amd64.deb"

Put in the version you actually have in place of <version>, and change the filename or path if yours differs. The byte count must equal the size given for that file, and the SHA-256 value must equal the checksum, ignoring upper and lower case. If either differs, stop — you do not have the file that was published or sent to you, and no amount of retrying the installer will change that. Download it again from the address above, or ask whoever sent it for another copy.

Why this matters more here than for most programs: this installer is not code-signed (see the next step), so Windows cannot tell you who produced it. The checksum is the only evidence you have that the file is the one that was built for you, and checking it takes ten seconds.

2. Installing it

Linux

For the Linux .deb package, open Terminal and install your downloaded file:

sudo apt install "$HOME/Downloads/toolsenabled_<version>_amd64.deb"

Replace <version> with the version you downloaded. Installation may ask for your administrator password. When it finishes, open ToolsEnabled from Applications as your usual user, then continue to section 3. The program is installed under /opt/ToolsEnabled; your settings are kept separately in your user profile.

Windows

  1. Double-click the downloaded ToolsEnabled-Setup-<version>.exe.
  2. Expect Windows to try to stop you. A blue box saying Windows protected your PC — Microsoft Defender SmartScreen. It is not a virus warning. It appears because this installer carries no code-signing certificate, so Windows has no publisher name to show you and nothing to check it against. To continue, click More info, then Run anyway.
    Whether it appears at all depends on how the file reached you: Windows shows it for files it has marked as coming from somewhere else, which a download does and a copy from a USB stick sometimes does not. Its absence is not a sign that this build is signed — it is not. If you are not willing to run an unsigned installer, that is a reasonable position; stop here and ask whoever sent it for a signed build.
  3. There are no further questions. No licence screen, no folder chooser, no Next buttons. A progress bar runs for a few seconds and the application opens by itself.

You will not be asked for an administrator password. The installation is for your Windows user account only. Work you later start can use the working folders and permissions you allow.

To open it again later

Press the Start button and type ToolsEnabled. Only one copy runs at a time: starting it a second time brings the window you already have to the front instead of opening another.

3. The first launch

The first time it opens you are asked four things, and then shown what your answers add up to before anything is written. You can press Back at any point, and nothing is saved until the last screen — except your permission level, which is recorded as soon as you pass question 1 so that closing the window does not send you back to the start.

  1. “How much should the assistant be allowed to do?” This is the important one, and it is the only screen of the five with no way past it except answering — there is no Skip here and it is not numbered, because everything after it depends on the answer. The three answers are explained in the next section. One is already selected, so if you do not want to decide yet, press Continue and you get the most cautious of the three.
  2. Question 2 of 3 — “Which folder should your assistant work in?” Review the suggested working folder shown for your computer. A new suggested workspace is created when you finish setup and initialized for version history. Press Continue to accept it, or Choose a different folder… to point it at a project of your own.
  3. Signing in. An optional step that asks who is using this copy, so that the record of what your assistant does says who asked for it. You can press Not now; nothing later in this page depends on it. If you do make one, note what the screen itself tells you: it is an account on this computer, not a sign-in to anyone's service. No OpenAI, Anthropic or Google password is asked for anywhere in this setup. After setup, What this copy needs has the separate install and sign-in controls for assistant programs.
  4. Question 3 of 3 — “How much should it do without asking you?” Three answers again:
    • Nothing yet — let me look around first. Every screen still reads and reports, and nothing that acts is switched on. Read the sentence under this option: while it is your answer, starting agents is switched off. The page explains how to turn starts on when you are ready. You can change it later.
    • Act when I start it. Marked Recommended, and it is what the rest of this page assumes. Action switches are enabled for work you start; this answer does not start an assistant by itself. Check the session's reported permissions.
    • Act on its own. Everything your permission level allows is switched on, and it uses its own judgement instead of waiting for you.

    The button forward from this screen is not called Continue — it says See what that sets, because that is what it does.

  5. “Here is what those answers set.” Every setting your three answers produced, each one changeable here. Review these before finishing; the permission level chosen earlier is already recorded. It lists what was switched on, what was left off, and which of those are off because your permission level does not include them. It also reports what it can prove about assistant readiness. The provider-neutral place to install or sign in is the in-app guide, where the buttons do that work. Press Finish setup.

The account row on Home opens Connect this computer in Settings. That connects this copy to a ToolsEnabled account; it is separate from every assistant program's sign-in.

Accepting every pre-selected answer takes five clicks from the first question to a working first page: Continue, Continue, Not now, See what that sets, Finish setup.

From question 2 onward there is a “Skip the rest for now”, and it is not the same as clicking through. Skipping applies the settings a computer that never ran setup already has — including “nothing that acts is switched on”. Clicking through applies the recommended answers, which leave you able to start an assistant. If you skip and then wonder where the start button is, that is why.

4. What the permission levels actually mean

The level selects available ToolsEnabled tools and the requested write policy for new sessions. You can change it in Settings. A working folder is not a promise that files elsewhere cannot be read.

“I’m new to this” — Guided

The assistant starts in one folder you pick. For Codex, Guided requests read-only work. Files elsewhere on the computer may still be readable.

“I’ve used AI coding tools before” — Standard

The assistant starts in the projects you add. Standard requests a restricted write policy; Codex can request writes within your projects and the program's temporary folders. Files elsewhere may still be readable. Your tool choices can narrow what the session can do.

“I run agents with permissions bypassed” — Unrestricted

The assistant can read, change and delete files and run programs without asking, subject to the operating-system account's access. Choose this only if you intend to allow that work.

Check the running session's reported permissions before relying on a write restriction. A session started or resumed here receives the requested permissions from that point; this does not undo earlier work. If you only watch a session that keeps running in another program, that program still controls its permissions. Choosing a level here does not change that process.

5. Getting an assistant program or local model ready

ToolsEnabled starts the provider you select and records the attempt, but it does not replace the provider's account, quota or sign-in. The Setup page is the source of truth for what this build can run; a row that is unavailable stays unavailable rather than silently selecting another provider.

  1. Open quick settings with the gear, then press all settings →.
  2. Choose Setup, then press Open the guide.
  3. Under Your assistant programs and local models, use the row for Codex, Claude, Gemini or Grok. Press Install if it is missing, or Sign in if the provider says it is not authenticated. A local model uses the controls on this computer and has no provider sign-in.
  4. Complete provider sign-in in the window the app opens. Enter provider credentials only in that provider's sign-in flow. ToolsEnabled uses the resulting sign-in to launch the selected assistant.
  5. Return to the setup review and press Check again. Read each provider's status and the model menu's availability message before starting; an unknown sign-in is not a confirmed failure.
  6. To permit starts, turn on Run an agent session in Settings under Write, then press Save settings. This switch controls new starts; it does not erase saved trees.

6. Starting, talking to and stopping an agent

After a provider is ready and Run an agent session is on, open Computers. A role is optional: a blank role is valid. Leave No particular role selected for an empty role, or choose one from the Role library when you want its directions.

  1. On #/computers, choose a saved tree or press the dashed + circle to set up the first agent. The start panel asks for its role, model, thinking effort, working folder and What do you want it to do?
  2. Set this agent saves an unstarted draft. Start this agent saves the draft and requests a session. Press the action you intend once, then read the status. A model row says if this copy cannot start it.
  3. A refused or failed start keeps the node and its outcome visible. A resource hold can put a start in the queue. Use Pause queue or Cancel queued when offered; cancelling queued work does not stop a session already opening.
  4. Select the node to open its rail. In Chat, type a message and use Send or Enter. Read the result before retrying a refused or unconfirmed send. Unaccepted text or a queued message can remain available to retry.
  5. The composer's Stop control interrupts the running turn and keeps the session open. Stop this agent closes the session and drops queued messages; the transcript remains. Resume with a fresh agent resumes the saved conversation. Start this conversation over starts fresh without its earlier conversation.
  6. The rail's Details tab contains Start more work, with Launch, Team, Loop and Codex Cloud controls. Each panel states its own requirements. Closing the rail leaves the node on the tree.

Read the recorded outcome in the tree status and Metrics. A status of unknown means the result was not established; it is not converted to idle, closed or done. Check the session before retrying an action whose acceptance was not confirmed.

Codex Cloud launches real remote work. Launching requires the desktop app, the Cloud switch enabled and a usable authorized environment. The panel explains switched-off and unavailable states before those conditions are met. Review the repository, branch and account at confirmation. A task cannot be cancelled after acceptance from this panel.

Reliable human and agent input

Press a visible label or the control itself and wait for its state to settle before the next action. For a text box, confirm that the caret is in the field and that the text appears, then submit once. A covered, disabled or off-screen control is not a successful click. Browser automation should use real pointer and keyboard events, wait for the route status or visible result, and read the field back after typing; do not assign .value or call a hidden .click() as a substitute for a user action. On a slow computer, allow the status sentence to settle and capture the exact refusal before retrying.

Where lag comes from

First reads, provider startup, reconnecting services, large trees and a busy CPU or low memory can all delay a control. The app shows Connecting, Reconnecting, unavailable or an explicit refusal when it knows which case applies. Keep one action in flight, avoid duplicate Start/Send presses, and use Refresh or Check again only after the current read finishes. If a page remains slow, record the page, control, exact sentence, elapsed time and whether the problem occurred on Windows or Linux.

8. When the product says something is missing

ToolsEnabled refuses in sentences rather than error codes, and every refusal below is one that tells you what to do. These are the ones a new installation actually hits.

What it saysWhat it meansWhat to do
Codex is not installed on this computer Correct — assistant programs are separate and we do not bundle them. Step 5, then press the program's Install button.
Codex is installed but nobody is signed in to it The install worked; the sign-in has not happened or has expired. Step 5, then press Sign in to Codex.
Codex … did not answer when asked its version The version check did not finish successfully. A slow check, incomplete install or broken launcher can cause this; the result does not prove which one happened. Open What this copy needs and use Codex's Install button again. Its own output appears there if the install stops.
this computer has not been set up yet The permission choice required for a new session has not been recorded. The start is refused. Open Settings and choose a permission level.
this copy shipped without … reinstall ToolsEnabled from a complete build A piece of the application is genuinely missing from the copy you were given. Nothing you can change will fix it. Ask whoever sent you the installer for a complete one. This is our fault, not yours.

9. Screens with no data yet

A page can be empty for several different reasons. A local page with no saved runs or ledger rows is showing your actual empty record. A relay-backed page can say disconnected, unavailable or waiting for history; those words mean the read was not established and must not be read as zero. The Computers page can have no saved trees until you set or start an agent, while Research and Comms can have no items even when the app is working.

To see a worked example, open Settings → What the screens show and turn on Show the example fleet. The example badge is explicit and does not connect to another computer or provider. Turn it off to return to your own records.

10. Starting over, and removing it

Change the answers you gave

Everything the walkthrough set is in Settings, individually, including the permission level. Change it there rather than reinstalling — a reinstall does not clear your answers, so it will not do what you want.

Uninstall

On Linux, remove the toolsenabled package with your package manager. This requires administrator permission and leaves your user data in place.

On Windows, open Settings → Apps → Installed apps → ToolsEnabled → Uninstall. No administrator password is needed.

Uninstalling does not delete your data. The record of what ran, your settings and your permission level stay in your user profile, so reinstalling picks up where you left off. On Windows these include %APPDATA%\ToolsEnabled and %LOCALAPPDATA%\ToolsEnabled. If you want them gone, delete those two folders by hand after uninstalling. That erases the signed record of everything that has run, which cannot be recovered.

11. Getting help

There is no support address, no help desk and no community forum. Not “we will get back to you slowly” — they do not exist yet.

If somebody gave you the installer directly, contact that person for help. Include these two details so they can identify the problem:

  • The exact sentence on the screen, copied or photographed. This product's refusals are written to name a cause; the sentence is worth far more than “it did not work”.
  • Which of the steps on this page you had completed when it stopped.

Two things can be genuinely somebody else's to fix, and going to them directly will be faster:

  • The assistant program itself — if its own install or sign-in window reports a failure, copy that exact sentence. It comes from the program's maker; ToolsEnabled shows the install output but does not replace or modify the provider's program.
  • The SmartScreen warning — that is Windows, doing what it is supposed to do about a program with no code signature. Nothing we can change from your end; the fix is a signed build, which has to come from us.

The source repositories are private. Official installers are available at toolsenabled.ai/download. Check that address before installing a download offered elsewhere.
