# Fields, generated controls and experiment admission

Research builds experiment apparatus. The investigator supplies the scientific
choices and control values through fields; the platform compiles the task,
execution contract, controls, runnable export and evidence reports. It does not
write a paper or infer a missing scientific decision from a successful run.

New drafts use specification version 2 and default to an experiment with required
controls. The frozen `readiness/contract.json` and `readiness/population.json`
identify the supported design, exact primary population, missing capabilities
and required executed proofs. `node cli.mjs readiness`, Research and the portable
runner derive the same decision. Static eligibility permits the required
preparation; only its fresh successful evidence permits the next trial.

## Investigator workflow

1. Fill in the task or generated template fields, recursive composition,
   conditions, inputs, population, protocol and supported dependence treatment.
2. For interpreted answers, prepare the requirement fields. Research enumerates
   every task, admissible reading and composition occurrence. Supply activation
   rules, hand-checked input/output assertions and plausible wrong readings.
   Generic interpretations also require two distinct source-pinned modules.
3. Apply those fields to generate the requirement plan. Changing a bound task,
   reading, input or source invalidates the old field roster. Applying a plan
   neither executes its controls nor grants personal review.
4. Review and freeze the resulting project. Inspect concrete blockers and the
   scope of each required proof. Export the code and run it through the CLI when
   independent local interpreters are needed; the browser does not pretend to
   execute those processes.
5. Inspect retained preparation, response, observation and report artifacts.
   Failed, incomplete and interrupted work remains visible and charged under
   the frozen budget rules.

The resource action-plan template generates its own reference plans, selected
case controls, bounded fresh Map executor and independent observation checks.
It uses the same admission contract without requiring a manually authored
semantic requirement plan.

## Three explicit execution purposes

| Purpose | Available work | Meaning of outputs |
| --- | --- | --- |
| Experiment with required controls | Supported design and collection path after all required fresh preparation and existing gates | Evidence for the declared endpoint and supported scope; no automatic scientific or personal approval |
| Recorded answer-key diagnostic | Canonical replay with owned supported grading | Consistency of saved responses and their frozen grading rule |
| Test unfinished apparatus | Explicit version 2 development in the qualification cohort, finite budgets and existing applicable execution gates | Unqualified development computations, including any analysis intervals; never scientific admission |

The development purpose lets an investigator implement and debug a grader,
interpreter or adapter before its scientific admission mechanism exists. The
journal binds its purpose. Reports retain that scope, including reference-audit
ancestry, so relabeling a cohort or selecting a passing result cannot upgrade it.

Version 1 projects retain exact reconstruction and their original scope. The
current runner supports their canonical replay diagnostics and completed resume;
it refuses new external or custom collection under a legacy identity. Previously
exported runtimes retain their versioned behavior.

## Current supported scope and remaining capabilities

The version 2 scientific design crosses frozen tasks and conditions with repeated
measurements and a binary primary endpoint. It supports descriptive analysis or
the declared family bootstrap. Complete primary denominators include scheduled
trials; repetitions are not independently sampled tasks. Unsupported design
fields are refused rather than ignored.

Experimental HTTPS collection uses exact request-context fields. An ordinary
condition declares `contextConstruction: "frozen-public-request"` and
`sessionIsolation: "fresh-request"`. A condition assigned to a frozen workflow
declares `"frozen-workflow-projection"` and `"fresh-call-requested"` instead; its
requests include only the task visibility and ancestor outputs selected by that
workflow. Having a workflow on another condition does not grant this capability.
Shared-history instructions and arbitrary context narratives cannot admit an
experiment. Development and legacy records retain their original declarations.
The derived contract describes sent requests: provider adherence, hidden history
and actual session isolation remain unobserved. These fields do not authenticate
a provider or prove that it complied with a fresh-session request.

Generic and LEAN semantic answers require complete selected-input composition
qualification. LEAN operational JSON prompts state the public chronology and
observation format; these are semantic answers, not candidate programs executed
by LEAN. Native candidate experiments remain blocked pending the applicable
source/image/data/observer/control admission mechanism and original native gates.
The existing bounded native development path does not grant that admission.

The resource template executes one returned plan against a fresh synthetic Map.
Filesystem effects, live services, arbitrary interactive agents, shared state,
concurrency, confidentiality loss and general severity measures require further
implemented capabilities. A named paper does not select an undocumented special
case: its methods must resolve to supported fields and mechanisms or explicit
missing requirements.

Full intended LEAN catalog, personal atom/RACE choices, native study qualification
and final app/engine release remain separate obligations. These controls make
missing apparatus visible; they do not close those obligations.

## Integrity and durable preparation

The runner takes a private immutable snapshot of the verified project, response
and journal records. Adapter and persistence callbacks cannot rewrite the answer
key or mutate a response between persistence and grading. Report generation
reverifies its private project snapshot before accepting retained outcomes.

Resource conformance writes a durable preparation intent before doing work and
pairs its terminal result and measured budget charge. Explicit recovery charges
an open intent's complete reservation with unknown elapsed time; it does not
invent a measurement. This local Map check owns no child process. Selected-input
preparation and actual resource episodes retain their stricter unresolved-process
and partial-effects halt rules. Legacy missing timing stays unavailable.

These checks establish consistency of retained bytes and enforced runtime
behavior. They do not authenticate a provider or hostile embedding host, prove
that two human-authored modules are scientifically independent, or replace
review of the experiment's actual scientific choices.
