# Check retained native evidence

Use this flow to inspect a settled LEAN apparatus run whose candidate and native result files are still available. It checks consistency without executing a candidate, native host, grader or provider. It supports modern schema-2 synchronous and operational projects. An archive alone cannot establish who executed it or qualify an experiment.

1. In the extracted project directory, run `node cli.mjs verify-native`. Use `--output DIRECTORY` if its retained results are elsewhere. Keep the original project, inputs and results available.
2. The command verifies the frozen project and settled journal, all 45 pinned runtime files and declared inputs, and each completed candidate's artifacts. It writes new `native-evidence.json` and `native-verification.json` in that result directory. Existing outputs are preserved; do not delete earlier receipts to conceal a changed archive.
3. In Research, import the matching draft and freeze the exact project. Open **Run & export**, then **Verify native evidence**, and select `native-evidence.json`. The page recomputes the same verification and summary before replacing its current evidence.
4. Export the separate verification receipt. It is kept only in the current view. Editing or freezing the draft, changing project/account, running recorded responses, or importing ordinary run evidence clears it. Draft saves retain no artifact verification. Ordinary report exports keep their existing statistics and execution scope.

The receipt binds the exact project and journal, decoded source/input/artifact hashes, retained response, candidate, reconstructed observation and complete grade. The process record must agree with the grade and deterministic attempt directory. Configuration and public operational harness bytes are reconstructed. Successful observations require a zero exit code and no signal; result and order-event files are discovered independently of the grade's file list. The canonical observer derives the trace, and interpretation grades include the complete matching reading set and declared scope.

Non-answer and no-program outcomes are rederived without inventing execution evidence. Ordinary nonzero engine exits can support only an explicit failing execution grade. Valid failed, cancelled or interrupted journal rows remain in the bound journal; they do not acquire completed native proofs. Open attempts refuse verification. Signals, timeouts, infrastructure exit codes, unknown completion and invalid engine results require additional provenance and remain outside this contract. Their existing development and version-1 audit inspection behavior is preserved.

The command rejects symlinks in file or directory components, incomplete journal writes, files larger than 16 MiB, aggregate captured inputs larger than 64 MiB, and encoded bundles larger than 64 MiB. Required files cannot be omitted; optional raw artifacts that exist are included and hashed. Unrelated normal files such as engine logs are not inputs to this contract. Bundle file maps must contain exactly the planned required and present optional files. Binary input bytes use an explicit base64 representation. Neither a caller's verification flag nor an outer hash substitutes for these checks.

The label is **retained-artifact-consistency**. A receipt does not authenticate execution, verify the image build or mounted market data, establish preparation or isolation, admit scientific collection, or approve an investigator's choices. The frozen analysis denominator is unchanged. Native experiment admission remains blocked until its separately required qualification and preparation contract exists. Historical projects retain their original bytes and versioned inspection paths; this command does not migrate or relabel them.
