# .45 cut regression investigation

The investigation found gaps in qualification as well as defects in the program
being qualified. A working development session did not establish that the exact
installer source, dependency tree and packaged program worked together.

## Latest source and native retakes

A later unchanged-source differential separated 20 native fixture failures from
product defects. Those tests failed under a group-writable scratch ancestor and
passed under a private root with trusted ancestry. Creating only the final child
directory with mode 0700 did not repair its unsafe parent. The strict launcher now
refuses that setup before measurement; it does not change directory permissions
or relax account custody. The remaining failures in that retained run included
omitted census entries and stale closure, message-surface and selector fixtures.
Their focused repairs do not replace a new complete run on frozen inputs.

The native first-use checks passed their saved-value assertions, but reviewing
their actual Settings screenshots found a presentation defect: the protected
permission choices were displayed in reverse order under the protection labels.
The renderer now retains the already protected-first choice order. The saved
values and permission policy were not changed. This is why a source suite or
scripted UI pass alone cannot qualify all visible controls.

The claims regression used to replace the shipped help module temporarily while
testing a refusal. An interrupted test or simultaneous build could capture that
temporary text. It now changes a private fixture containing the unchanged checker
and copied inputs, and verifies that the original help file was not rewritten.
Tests and build inputs must remain separate even when cleanup normally succeeds.

Empty role selection exposed a similar coverage gap across layers. Start
validation allowed an empty selection, but the host subsequently injected Worker
instructions. An explicit node-bound empty selection now survives authoritative
seat preparation, start validation and onboarding without erasing capability or
account checks. Independent review then found that the actual SQLite continuation
schema rejected the new field: the first regression had stubbed the continuation
writer. The follow-up exercises the real controller, database close/reopen and
fresh role validation, including refusal when an assignment changes. Selected
custom roles also accept empty instruction strings while retaining their identity,
function policy and revision requirements.

The broad native role scenario driver still referenced the earlier inline role
editor after Role Studio replaced it. Its migration and full native retake are
separate from the focused empty-role editor evidence. Likewise, synthetic provider
replies, completed DOM input and private structural delivery remain distinct from
an installed provider-backed start, response, Stop and persisted recovery.

Independent tree review of the approval repair exposed two more shared UI
defects. Rebuilding the rail card discarded its local answer lock; a late
answer could also remove a newer permission with a reused provider id. The
actual rail and chat handlers reproduced both failures. They now share answer
ownership per pending request, including repaint, cancellation and late replies.
Halt clears only the permissions present when its confirmed request began, so
an acknowledgement cannot erase the next turn's questions. A pending count on
the rail makes its sequential permission cards visible to someone outside chat.

Fresh native setup also exposed a repeatability gap. Stop correctly ended npm,
but a second interrupted install could leave its deterministic package-retirement
directory occupied. The next Install press then failed with `ENOTEMPTY`. The
shared installer now asks the same npm for its configured global root, moves
only the selected package's exact retirement directory aside, and retries once.
Each stage retains the existing process-tree cleanup requirement and Stop
control. An actual offline npm fixture reproduced the collision, recovered it,
installed the new local package, and ran its executable. A new desktop build
must still repeat the hand test; a manually repaired diagnostic profile is not
installation acceptance.

## Source and dependency identity

The third diagnostic cut declared one engine commit, but its engine checkout
changed during the source tests. Its results therefore describe a mixed source
pair and cannot qualify either commit. The cutter now verifies the declared
engine binding before and after every operation. Final qualification uses a
separate frozen engine checkout.

The fourth attempt caught another source-isolation error: the engine census ran
in the same checkout used as the cut input. Some tests temporarily alter their
fixtures there, so an exact-pair check correctly refused that transiently dirty
source. Engine tests and untouched release inputs now use separate checkouts of
the same commit. A checkout running tests is not an immutable build input.

Reusing a development dependency directory also let the cut inherit inputs that
were not described by its lockfile. Real Linux cuts now require `npm ci` in the
new build worktree. Dependency reuse remains a rehearsal option. Real resume
cannot reuse earlier records whose ignored build inputs were not bound.

A disposable npm fixture confirmed that root `preinstall` runs after `npm ci`
removes an existing dependency tree, even when the hook then refuses. Existing
dependency replacement needs the separate preflight already used by the reuse
helper. Fresh Linux cuts avoid that existing-tree replacement altogether. The
Windows holder check also misidentified an `electron-shadow` sibling as part of
`electron`; canonical, segment-aware matching now distinguishes them and
recognizes linked dependency directories.

Implicit source selection also silently excluded staged, unstaged and untracked
fixes: the cutter resolved HEAD and built a clean worktree without first asking
whether that commit included the work visible in the owner checkout. A real Git
fixture reproduced all three omissions. Both cutters now refuse implicit HEAD
from a dirty checkout; an explicit exact source commit remains a deliberate
selection. The regression failed before the change and passed afterward.

Native Windows qualification found that inherited `PSModulePath` could prevent
Windows PowerShell from loading `Get-FileHash`. Installer verification now reads
the size and SHA-256 from one read-only .NET file handle, retaining exact-byte
refusal and rejecting same-size tampering even without that optional cmdlet.
The Windows agent measured all 70 packager cases passing; the same group on
Linux passed its 69 applicable cases, with the native Windows case explicitly
skipped. The four adjacent Linux cut/version/note suites passed all 42 cases.

## Ratchet defects

The engine's old package ratchet compared totals. Removing one old boundary
violation and introducing a different one at the same total passed. Baseline
writing could also absorb a larger total. Tests reproduced both failures.

The engine now records exact finding identities, initially reconstructed from
the original committed baseline. New identities fail even when totals fall;
the writer cannot replace missing, unreadable or regressed evidence. The app's
test ratchet similarly refuses new failure identities during baseline updates,
and its source fingerprint includes configuration, public assets and documents.

The stronger engine check exposed new ownership errors and upward dependencies.
Repairs assign pure confinement/account policy and owned-process cleanup to
their actual shared packages; separate opaque file-capability lifetime from
transport validation; share saved-setting validation with kernel tuning; and
compose Ledger and purchase policy through their existing public entrypoints.
Existing authority, revocation, reset and Stop checks remain exercised by tests.

## Incomplete or misleading evidence

Sixteen source suites were absent from the app's required census. They are now
required. Packaged UI failure now stops the cut before installation and tagging.
The tag operation also requires every applicable preceding result, including
the installed smoke and onboarding evidence, to be complete and successful.
Pending operator work and relabeled prior records cannot establish a pass.

TAP parsing mistook quoted failure text for structure. In addition, temporary
cleanup deleted an earlier failed run's raw output, and retaining output only
at child completion still lost diagnostics after interruption. The parser now
handles quoted diagnostic scalars; stdout and stderr stream immediately into
private retained files, with a completion record written only after the child
finishes. The packet's install details are measured from the exact package.

The engine census also printed `DONE baseline recorded` after failures and
timeouts, although it correctly returned exit 1. It now names the result
`PASS`, `FAIL` or `INCOMPLETE` and calls its output a measurement. Recording a
run does not accept its failures or update a ratchet baseline.

## Native process lifetime and timeout ownership

The isolated engine runner used a synchronous child timeout that stopped only
the immediate process. Native reproductions showed descendants continuing to
write after both timeout and normal root exit. A subsequent test could run
while that old work was still using its scratch directory. The repaired Linux
runner retains the existing subreaper/pidfd supervisor and waits for its empty
descendant-scope receipt before advancing or deleting scratch. Unproven cleanup
fails the run and preserves scratch. The native root PID, distinct from its
guardian, remains bound to measured assertion receipts.

The Linux acceptance entry contains 56 suites but received the same 180-second
outer deadline as one suite. Audit identity alone completed successfully in
216.701 seconds. The outer budget now derives from the actual entry's child
selection and each child's bounded budget, using the existing static invocation
reader. No duplicate selection or unconditional timeout exemption is introduced.
Individual host-byte and audit suites also receive measured enclosing budgets;
their operation deadlines and assertions remain in force.

Separate native fixtures killed their own prerequisites: several agent tests
allowed 250 milliseconds for guardian, root and detached-leaf startup, and the
desktop fixture killed Xvfb after 15 seconds during a sequence measured at
22.386 seconds. Their repaired lifetimes let the tests reach the intended real
timeout, Stop, capture and descendant-reaping assertions.

## Runtime wiring and long tool results

The desktop's continuation, audit-maintenance and Ledger-reset loaders were
absent from the engine's external invocation roots. Their declarations now
name the real shell callers; ordinary imports establish their internal closure.
An older Ledger gate writer had only test callers. Its compatibility logic is
retained as an excluded test fixture with a required explicit ledger path,
instead of inventing a product caller or allowing a fixture to use the owner's
default ledger.

A real tree Codex request allowed `host.exec` 600 seconds, but its MCP client
stopped waiting at 300 seconds. The command completed later, leaving the agent
without its result. Generated ToolsEnabled MCP entries now set
`tool_timeout_sec = 900`, allowing the existing ten-minute command bound plus
auditing and cleanup. Stop and command authorization are unchanged. The
[supported MCP setting](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
was also accepted by the installed Codex configuration parser. Installed .45
acceptance must still demonstrate a real result after the old five-minute limit.

## Program and fixture defects exposed by the cut

These failures were not all caused by packaging. Examples include a relayed
agent graph hidden by an empty local tree store, an unplaced chat lost on page
navigation, and Linux OAuth opening Text Editor because the scrubbed launch
environment omitted desktop browser discovery paths. Their repairs require
functional checks of the affected flows.

Several fixtures also lagged behind source changes: extracted functions lacked
their real closure dependencies, UI stubs lacked lifecycle methods, and native
qualification created an unsafe profile mode under a permissive user umask.
One native role check had a deadline shorter than its measured successful run.
The repaired harness uses private profiles, retained stage/error diagnostics,
and an owned-process deadline that includes descendant cleanup. Fixture repairs
are not substitutes for packaged and installed testing.

The next complete engine census failed one browser-authorization file while
focused runs often passed. Failure diagnostics showed repeated real hello frames
reaching the machine, where the introduction was rejected as malformed. The
fixture sampled `Date.now()` twice for one grant's two expiry bounds; a clock
tick between those reads made authorization last one millisecond longer than
its transport. The production parser correctly rejects that relationship.
A clock that advances between reads reproduced the timeout deterministically.
The fixture now samples the expiry once. Its new regression case completes the
real fixture handshake and request with consecutive clock ticks. The real
thirty-second authority ceiling, expired-session error translation, and all
thirty parser boundary cases still pass; no timeout or authorization check was
relaxed. The failed census is retained and a fresh complete census is required.

## Fresh provider profiles and approval interactions

Fresh desktop preparation exposed two account-isolation defects that an existing
signed-in development profile could conceal. The private-home registry omitted
Grok, and the shared subprocess transport selected Codex's home and executable
even when called for Grok or Gemini. The provider now travels through detection
and launch, with the selected provider's own registered sign-in file. These are
runtime wiring defects exposed by a fresh profile, not evidence that a cutter
deleted the corresponding features.

A genuine Grok tool call then reached a permission request that neither approval
surface could answer correctly. The host sent `{decision}`, while the ACP adapter
only accepted its native outcome record. Chat additionally invented Codex's
`accept`/`decline` pair instead of carrying Grok's offered option ids. Existing
tests covered rendering choices and rejected host answers separately, so both
ends passed without a successful interaction between them.

The shared UI now carries the actual choices, scope and tool context. Its host
path accepts bounded opaque ids; the adapter translates only an exact offered
choice. Pending permissions have unique handles bound to one active turn and
are cancelled at Stop, completion and close. Multiple requests remain individually
answerable. A new real host/adapter test fails on the old adapter and passes on
the repair; an installed private Grok client completed an approved diagnostic
tool call and confirmed cleanup. Fresh rebuilt-desktop and final installed-cut
acceptance are still separate requirements.

Windows also exposed Codex native worker events multiplexed into a parent
connection. The adapter now tracks workers only after a validated parent
announcement, keeps host and worker identities distinct, and refuses worker
approval authority. Native Windows recovery and focused Linux checks support
the repair; neither is a substitute for the final paired installer tests.

## Platform packets and release-note order

The Linux cutter filled its own install record but retained an unfinished Windows
record. Declaring both platforms therefore made the final Linux note check fail
while waiting for the Windows cut that was supposed to run second. Conversely,
the Windows command ran its source-note check only after creating the build tag,
and never produced a measured packet note of its own.

The source plan now explicitly names Linux and Windows with pending measurements.
Each cutter checks that full inventory, then emits and validates only its own
measured install record before tagging. Windows also measures signing status and
rechecks the staged bytes. Neither platform packet qualifies the other platform;
publication must combine the records from both completed cuts.

## Research state and late writes

Research submissions captured a project but could continue after the page or
account changed. Local worker listeners also used whichever account row had most
recently seeded the module. Account reads now identify their actual owner, and
optional write comparisons are checked against the host's current session before
partition access. A caller cannot select a different account with that comparison.
Worker outcomes retain their original account context and remain unsaved, with a
visible reason, until a matching account can accept them.

Separate reproductions found missing first-send transcript bindings, terminal
events arriving before the first acknowledgement, and saved local workers that
were not observed again after reload. The dispatcher binds the native session
before sending, and reload queries actual session status and matching transcript
entries instead of launching replacements or assuming an old status is current.

Save and Remove still wrote outside the worker-result queue. A controlled browser
check reproduced a removed design returning when another worker completed during
the removal's acknowledgement. Design edits now reserve that same queue and apply
membership changes only after acceptance; later result writes include the accepted
edit. Refused edits preserve existing membership. An older account read cannot
overwrite a change accepted while that read was in flight.

Two UI fixtures had also kept testing retired controls or prose: the chat menu's
New tree action had replaced the empty-slot shortcut, and Settings used a shorter
missing-report sentence. Their checks now exercise the current controls and keep
the original behavior and truthful-copy assertions.

## Cloud command routing

Current chat rejected `/cloud` as unknown even though the engine still exposed
account discovery, task launch, status, and diff retrieval. The available source
history did not establish which cut lost the original command, so that causal
claim remains unproven.

The command now uses one parser shared by the renderer and installed native
host. A person-origin turn supplies the coordinator's cloud workflow: resolve
the current project and registered accounts, split the work within the selected
worker limit, retain actual task IDs, reconcile uncertain launches, retrieve
results, and verify the requested changes. Bare `/cloud` uses the conversation's
current objective. Optional worker choices in Actions edit the originating
composer; they do not send or require setup before the direct command works.
These are agent instructions, not a new deterministic swarm scheduler or a
replacement for the engine's launch policy and account checks.

Cloud requests use the ordinary durable outbox, including Send now and recovery.
Product-only commands remain intercepted immediately. The accepted transcript
retains both the person's exact command and the actual host-added instructions.
Cloud input also marks an agent as prompted by the person, protecting it from
automatic removal. Invalid options and oversized requests refuse before a native
turn begins.

Focused checks passed:112 composer/host/queue/recovery cases and143 adjacent
cloud/account/transcript cases. The renderer builds with the shared installed
module. Actual native cloud execution and final installed acceptance remain
required; these source checks do not qualify an installer.

## Qualification status

These findings explain why earlier evidence was insufficient. They do not by
themselves qualify .45. A release requires a new complete cut of the repaired,
frozen source pair, fresh dependencies, packaged checks, and actual installed
hand testing on both Linux and Windows. A discovered functional defect fails that
attempt and requires a new cut after repair. An interrupted engine census is also
incomplete even when its recorded tests passed; the replacement census runs as a
managed process with an independently observable final exit status.
