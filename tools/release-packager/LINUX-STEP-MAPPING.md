`1c38d09d697608f1b83688bd9240404ecd0974d2` (the base-pair app commit). `cut :N` means

Driver step numbers (`D01`…`D62`) are the `--plan` numbering of

Treatment vocabulary:

- **KEPT** — the same tool, same arguments (or the same argument with `release/win-unpacked`
  replaced by `release/cut-<v>/linux-unpacked`), run as a recorded child in the worktree.
- **REPLACED by …** — the Windows-only tool cannot run on Linux; the named Linux equivalent runs
  in its place. Each cites the file:line that makes the original Windows-only.
- **NOT APPLICABLE** — only for NSIS/PE specifics; each names its dpkg/ELF replacement.
- **requiresOperator** — unexecuted, recorded with the exact command; runs inline only with `--installed-proof`. Pending installed smoke or onboarding blocks a release tag and completion.
  (needs non-interactive sudo and a desktop session).

2. `packaged-qa-suite` on Linux (D53): **Required for .45 acceptance.** The current owner request requires failed cuts to be repaired and repeated. This supersedes the historical non-stopping Linux exception. The complete default suite must pass against the exact candidate before installation or tagging. Sealed smoke and manifest checks remain additional evidence, never substitutes for a failed UI journey.

   What changed is the reason the step could not produce one. The 1.0.44 note above named four causes; re-measured on 2026-09-11 against this tree, they resolve to a much smaller set than the note claimed:

   - *"`sterile-launch.cjs` is `path.win32`"* — **was already wrong at 1.0.44.** `filterForeignWindowsProfilePath` returns its input unchanged off win32 and `sterileLaunchEnvironment` has a full Linux branch (HOME + XDG_CONFIG/DATA/CACHE/STATE).    - *"35 of 86 name `ToolsEnabled.exe`"* — **9 name it; 33 name `win-unpacked`.** Both were single hard-coded defaults (`packaged-qa-suite.mjs` `DEFAULT_RELEASE`, `test-account-harness.mjs` `releaseDirectory()`), and `appExecutable()` already had a complete Linux ELF branch. 60 of the 86 drivers reach the artifact only through `tools/test-account-harness.mjs`, so those two defaults were the whole of it.

   **One named skip**, following the `RELEASE_SKIP_REGISTER` `requiredPlatform: "win32"` convention (reason and all): `nsis-upgrade-roundtrip-qa` — its one check is an NSIS installer upgrade round trip driven by `powershell.exe -File tools/nsis-upgrade-roundtrip.ps1`, and its Linux counterpart is the dpkg chain already in this driver (D46, D51-D52, D56).

## Qualification integrity in .45

Release cuts always begin in a fresh worktree with fresh lockfile dependencies. `--resume-from-step` is limited to diagnostic rehearsals: the earlier Linux record did not bind all mutable ignored build inputs and could relabel pending operator steps as accepted. Each cut step verifies the engine commit and cleanliness before and after execution. The immutable tag requires every preceding applicable proof, including packaged UI, installed sealed smoke and onboarding, to have actually passed. Rehearsal records never create a release tag.

The source ratchet retains complete private diagnostics outside disposable cut scratch, parses TAP diagnostics without treating quoted text as test structure, and fingerprints source, configuration, public assets and release documentation across measurement. Development `--update` can only lower its reviewed failure set; release qualification accepts no failure baseline.
